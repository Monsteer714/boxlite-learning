# Source Analysis: C Quick Start (BoxLite C SDK)

## Summary
This quickstart is the C-language entry point for BoxLite. It reveals the full C binding surface (`boxlite-c` crate): a two-tier API design — **Simple API** (`CBoxliteSimple`, buffered results) and **Native API** (`CBoxliteRuntime` + `CBoxHandle` + `CBoxliteOptions` + `CExecutionHandle`, streaming callbacks) — plus structured error handling, memory-management rules, and a suite of 8 examples. Notably, it is the first source in the wiki to describe a *non-CLI/SDK-language-specific* binding layer with explicit C types, build outputs, and platform requirements.

## Key Concepts

1. **Two-tier API design (Simple vs Native)** — Simple API (`CBoxliteSimple`) trades control for ergonomics: `new` auto-creates *and* auto-starts, `run` buffers output, `free` cleans up. Native API exposes runtime → options → create_box → streaming execute → wait, with explicit ownership. This is the most architecturally significant idea in the doc and is not yet captured in the wiki.
