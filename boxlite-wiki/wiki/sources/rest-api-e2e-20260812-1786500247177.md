## Key Concepts

1. **REST E2E flow (SDK → API → Runner → VM)** — End-to-end verification through the public REST contract. The doc frames this as the canonical "not a local FFI test path" — i.e., real network/HTTP testing, not in-process library calls. Matters because it defines what "REST-backed" means and what remains local-only.

2. **API-key authentication** — Static key via `BOXLITE_API_KEY` / `BOXLITE_E2E_API_KEY`; the simpler, default mode. Documented precedence rule: API key takes precedence over profile/OIDC credentials.

3. **OIDC authentication** — Bearer token or browser login flow (`boxlite auth login --method browser`); token refresh behavior aligned to real CLI behavior via `boxlite auth whoami`. Operationally heavier (needs existing login/profile; requires `BOXLITE_API_KEY` unset).

4. **`path_prefix` discovery via `/v1/me`** — The API self-describes the mount prefix; both auth modes discover it by default, with explicit override via `BOXLITE_E2E_PREFIX`. This is a notable server-driven API design detail.

5. **CLI command matrix** — Maps CLI commands to REST API behavior across `smoke`/`full` scopes. Notably: `boxlite rm` is the supported command; `boxlite remove` does *not* exist.
