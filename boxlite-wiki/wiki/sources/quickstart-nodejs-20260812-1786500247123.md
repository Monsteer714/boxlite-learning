## Key Concepts

- **SimpleBox lifecycle pattern** (construct → `exec()` → `stop()`) — The core workflow. Construction takes only `{ image }`; execution streams stdout; `finally { await box.stop() }` guarantees cleanup. Consistent with lazy initialization (no pull/start at construction).
- **Async disposal (`await using`, TypeScript 5.2+)** — Explicit resource management pattern where the box is automatically stopped when leaving scope. Not currently in the wiki. This is the idiomatic modern-JS lifecycle pattern.
- **Exec vs. Run distinction** — `box.exec('python', '-c', ...)` appends commands to a live box, distinct from docker-parity `run` init semantics documented in [[concepts/run-command-semantics]]. The box is created without a main command, so exec works without triggering the restart-refusal guard.
- **First-run image pull** — "pulls the `python:slim` OCI image (first run only)" — reinforces [[concepts/oci-image-caching]] and lazy initialization.
- **Hardware virtualization requirement** — Node 18+ plus KVM/Hypervisor.framework platform; reinforces [[concepts/micro-vm]].

## Main Arguments & Findings

- **Core claim**: BoxLite Node.js SDK reaches a usable state in ~5 minutes: `npm install`, import `SimpleBox`, exec a command, stream output, stop. This is the "developer experience" promise backing the project thesis.
- **Secondary claim**: The SDK ships a hierarchy of specialized boxes (CodeBox, BrowserBox, ComputerBox, InteractiveBox), indicating a product family beyond basic command execution.
- **Evidence strength**: Weak empirically — this is prescriptive tutorial documentation with no benchmarks, but it is strong *evidence of intended API surface and DX*. It validates that the daemonless-embedding story works through a plain npm import with no root/daemon.
