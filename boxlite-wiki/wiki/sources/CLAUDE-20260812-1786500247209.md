## Key Concepts

- **Same-origin `/api` proxy pattern** — The dashboard only ever calls a same-origin `/api` path; Vite proxies it to the selected backend. This eliminates CORS entirely — no backend must allow-list `localhost`. A clean architectural trick worth preserving in the wiki.
- **`DASHBOARD_API_PROXY_TARGET`** — Environment variable coupling command choice to proxy destination, read by `vite.config.mts`. The mechanism that makes "select backend via npm script" work.
- **Auth-follows-API** — Login uses whatever OIDC issuer the selected API reports via `/api/config`. Security-relevant: the chosen backend determines identity.
- **E2E entrypoint discipline** — `npm run e2e:local` is the *only* E2E startup entrypoint; `start`, `start:dex`, and `serve-slim` must not be used directly for E2E. This is an explicit guardrail.
- **Two distinct E2E systems** — Browser E2E (`npm run e2e:local`, Nx-based) vs. pytest stack suite (`apps/e2e/`, make-based from repo root). The document explicitly disambiguates them, signaling a known confusion point.
- **OIDC** — OpenID Connect protocol; the auth mechanism for all non-mock modes, flowing through Dex locally.
