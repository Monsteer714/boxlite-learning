## Key Concepts

| Concept | Definition / Why It Matters | In Wiki? |
|---|---|---|
| **Credential Profiles & Precedence** | `BOXLITE_API_KEY` env > stored file > unauthenticated; named profiles via `--profile`/`BOXLITE_PROFILE`; multiple logins coexist in one TOML file. Central to remote workflow. | No |
| **Three-Login-Flow Authentication** | API key (long-lived, CI), browser OIDC (Authorization Code + PKCE, callback on 127.0.0.1:5555), device code (RFC 8628, headless/SSH). Method inference: piped stdin → api-key, TTY → picker, `$SSH_CONNECTION` → device. | No |
| **OIDC Session Refresh** | Access token auto-refreshes within 5 min of expiry; `invalid_grant` triggers re-login prompt; `auth status` is offline and prints no secrets; `whoami` makes `GET /v1/me`. | No |
| **Path-Prefix Routing Slots** | `--path-prefix` yields `/v1/<prefix>/boxes/...`; opaque to CLI, server decides meaning (org, workspace); captured from `Principal.path_prefix` at login; empty → `/v1/boxes/...` for single-tenant. | No |
| **Run-Command Semantics** | COMMAND replaces image CMD, ENTRYPOINT prepended, result is PID 1; box lives exactly as long as command; exit code readable via `inspect -f '{{.State.ExitCode}}'`. | Yes: [[concepts/run-command-semantics]] (confirmed) |
| **Config-Gated Restart Refusal** | `exec` against a finished box is refused, not silently restarted (would run command twice). | Yes: [[concepts/config-gated-restart-refusal]] (confirmed) |
| **Create-vs-Run Job Semantics** | `create` with COMMAND store
