# Source Analysis: AutoStop, AutoResume, and AutoDelete

## Key Entities

| Entity | Type | Role | In Wiki? |
|---|---|---|---|
| **BoxLite Control Plane** | System component | **Central.** Implements the lifecycle sweeper, submits `STOPPED` as desired state, creates/joins Start operations, enforces the `auto_delete` timer. The entire feature lives here. | Yes — [[entities/boxlite-control-plane\|BoxLite Control Plane]] |
| **Box** | Runtime entity | **Central.** Subject of the lifecycle; transitions `STARTED` → `STOPPED` → (delete). Reuses existing states; no new `Paused` state. | Yes — [[entities/box\|Box]] |
| **BoxLite cloud REST runtime** | Runtime mode | **Central.** The only environment where these policies are active. | Implicitly — not a dedicated entity in the index |
| **Embedded local runtime** | Runtime mode | **Peripheral but important contrast.** Explicitly returns `Unsupported` for these policies — no lifecycle sweeper runs. | Yes — [[entities/boxlite-runtime\|BoxLite Runtime]], [[concepts/daemonless-embedding\|Daemonless Embedding]] |
| **SDKs (Python, Node.js, C, Go)** | Client libraries | Peripheral; pass `auto_stop`/`auto_delete` at creation; read effective values from box info. | Implied — SDKs are referenced but no dedicated wiki pages |
| **Runner** | System component | Peripheral; the component that receives operations *after* the box reaches `STARTED` (AutoResume step 3: "forwarding to the runner"). | **Not in wiki index** — potential new entity or alias for an existing component |

## Key Concepts

| Concept | Definition | Why It Matters | In Wiki? |
|---|---|---|---|
| **AutoStop** | Automatic `Stop` after `auto_stop` seconds of idle; reuses the normal Stop flow, no snapshot, no new state | Core of the feature; cost control via idle detection | **No** — new |
| **AutoResume** | Automatic `Start` on the next Exec/Files/WebSocket operation; first request cold-starts, concurrent requests coalesce on one state transition | User-perceived "wake from sleep"; the key UX mechanism | **No** — new |
| **AutoDelete** | Deletion `auto_delete` seconds after the box *successfully* enters `STOPPED`; also armed by manual Stop; `0` cancels future deletion | Storage lifecycle; prevents orphaned persistent disks | **No** — new |
| **Activity semantics** | A curated allowlist of operations that refresh the idle timer / trigger resume; metrics and port traffic deliberately excluded | Prevents monitoring feedback loops from keeping boxes alive; defines what "user workload activity" means | **No** — new |
| **Desired state** | Control-plane abstraction: `STOPPED` is *submitted* rather than imperatively executed | Shows the control plane's reconciliation model (existing behavior, now repurposed for policies) | No — new |
| **Lifecycle sweeper** | Background mechanism that evaluates policies; explicitly absent in embedded runtime | Explains the cloud-vs-embedded feature boundary | No — new |
| **Persistence boundary** | Disk/volumes survive Stop
