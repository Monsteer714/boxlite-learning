## Key Concepts

1. **Workload-type sizing reference** — Recommended CPU/memory/disk per agent workload (code exec, data analysis, web browsing, multi-tool, persistent env). Establishes practical resource guidance rather than just API mechanics.

2. **Security presets** — `development()` / `standard()` / `maximum()` as a tiered security model. `maximum()` adds resource limits (`max_open_files`, `max_file_size`, `max_processes`) specifically for untrusted AI code. Extends [[concepts/sandboxing-layers]].

3. **One box, multiple executions** — A single VM serving many concurrent `exec()` calls via `asyncio.gather`. Justified because VM hardware isolation makes concurrent processes inside the same box safe. Avoids repeated VM boot cost.

4. **One box per agent** — Strict isolation between agents, different images, or independent resource limits. Contrasting concurrency model.

5. **Timeout handling / zombie prevention** — Core insight: `asyncio.wait_for()` does **not** kill the guest process; explicit `execution.kill()` is required. This is the document's most critical operational lesson.

6. **Read-only volume mounts** — Providing host data to the sandbox without allowing modification; tuple form `("/host/datasets", "/mnt/data", "ro")`.
