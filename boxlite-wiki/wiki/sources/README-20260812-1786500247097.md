## Key Concepts

1. **Platform support matrix** — Concrete requirements: macOS Apple Silicon 12+, Linux x86_64/ARM64 with KVM, Windows via WSL2 with KVM. Notably declares macOS Intel *unsupported* (Hypervisor.framework stability issues). Not currently a wiki concept.
2. **Daemonless operation** — "Unlike Docker, BoxLite doesn't require a daemon process. It's an embeddable library that runs directly in your application." Already captured as [[concepts/daemonless-embedding|Daemonless Embedding]]; this doc adds the explicit Docker contrast.
3. **KVM permission model** — `/dev/kvm` accessibility, `kvm` group membership, `modprobe` module loading; the "Timeout waiting for guest ready (30s)" error is diagnosed as a KVM permission symptom. New operational knowledge.
4. **SDK version floors** — Python 3.10+, Node 18+, Rust 1.88+, Go 1.24+ with CGO, C11. Concrete, citable requirements.
5. **Resource tuning via BoxOptions** — `cpus=4`, `memory_mib=4096`; surfaces the metrics API (`box.metrics()`, `memory_usage_bytes`).
6. **Storage location** — `~/.boxlite` as the data directory (disk-space troubleshooting).
7. **5-minute onboarding promise** — the doc's framing thesis: low-friction setup is a product differentiator.

## Main Arguments & Findings

- **Core claims:** BoxLite can be operational in 5 minutes; requires hardware virtualization; needs no daemon; offers five language SDKs; most installation failures are environmental (KVM permissions) rather than product defects.
