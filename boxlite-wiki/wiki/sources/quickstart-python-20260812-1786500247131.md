## Key Concepts

1. **Higher-Level Box APIs** — The quickstart reveals a four-tier API hierarchy: Core (Boxlite, BoxOptions, Box, Execution) and Higher-level (SimpleBox, CodeBox, BrowserBox, ComputerBox). Only SimpleBox exists in the wiki; the taxonomy itself is undocumented.
2. **Async context-manager lifecycle** (`async with boxlite.SimpleBox(...)`) — Box creation and teardown are governed by Python's `async with`; cleanup is automatic on context exit. Directly extends [[concepts/daemonless-embedding\|Daemonless Embedding]].
3. **CodeBox pattern** — `install_package("requests")` then `run(code)`; the recommended primitive for *untrusted* AI-generated code. The key design insight: dependencies are installed *inside the box* before code execution, so behavior is consistent across clean images and reused boxes.
4. **First-run image pull** — Image is fetched on first use only; subsequent runs reuse. Reinforces [[concepts/oci-image-caching\|OCI Image Caching]].
5. **Streaming output** — `result.stdout` / `print(result)` returns command output to the host. Relates to [[concepts/grpc-vsock-protocol\|gRPC over vsock (Portal protocol)]] as the transport but adds the user-facing result-object API.
6. **Isolation guarantee framing** — "Your host system remains completely safe" — user-facing articulation of [[concepts/sandboxing-layers\|Sandboxing Layers (Defense-in-Depth)]].
7. **Example-driven onboarding** — 9 examples across five categories (getting started, lifecycle, interactive, browser/desktop, advanced) serve as a de-facto capability map for the SDK.
